# 言語モデルにおける語彙獲得と語義追加の機構解析

[English](README.en.md)

OLMo 2（1B / 7B / 13B）を継続事前学習して語彙を人工的に操作し、新しい語が知識を獲得する順番と、文脈から語義を選ぶ機構を調べる実験のコードです。

## 実験の概要

| 実験 | 操作 | 問い |
|---|---|---|
| 実験A | 学習データ中の既知の名詞（例: pasta）を、モデルが見たことのない文字列（例: resonunt）に置き換えて学習する | 新しい語は「形への慣れ」「意味の獲得」「語としての統合」（定義は[実験A](#実験a)）をどの順番で獲得するか |
| 実験B | 学習データ中の既知語（例: grape）を別の既知語（例: car）に置き換えて学習し、car に語義を足す | 文脈から語義を選ぶとき、どの head が何の属性（名詞カテゴリ・品詞）を判定しているか |
| 接続 | 追加の学習なし。実験Aの重みの上で、実験Bで特定した head を無効化する | 語として統合された未知語は、既知語と同じカテゴリ判定の機構に依存しているか |

- 継続事前学習は60 run（実験A: 9 run × 3モデル、実験B: 11 run × 3モデル）。
- 主実験は 7B で行い、1B・13B は同じ手順でモデルサイズの比較に使う（[実行の順序](#実行の順序)）。

### 用語

| 用語 | 意味 |
|---|---|
| run / 対照 run | 1つの学習データでの継続事前学習1回 / 何も置き換えない run（実験Aでは何も差し込まない） |
| 未知語 | 実験Aで使う、モデルが見たことのない語。2・3トークンは文字列、1トークンは新しいトークン番号（管理名 `<new_01>`〜`<new_24>`） |
| near / far | 2・3トークンの未知語の綴りの種類。near は実在語から編集距離2以内、far は発音できる非語 |
| 置換元 / donor | 用例の中で置き換えられる既知語。実験Aでは名詞（置換元）、実験Bでは足す語義の元の語（donor） |
| ターゲット語 | 実験Bで語義を足される既知語 |
| 管理対象の語 | 実験で操作する語（未知語72個・名詞72語・形容詞72語・ターゲット語18語） |
| 自然な語 | 管理対象以外の実在語。プローブの学習、課題の例、確認に使う |
| 役割 | 語台帳で各語に付ける用途（名詞、ターゲット語、形容詞、未知語、自然な語の種類、予備の候補） |
| 標準形 | 用例で使う唯一の形。先頭スペース付き・小文字・単数（例: " pasta"） |
| 基データ / 検証データ | OLMo 2 の事前学習データ（olmo-mix-1124）を学習順に並べた先頭約3億トークン / その直後の約1,000万トークン |
| 用例 | Pile から切り出した、語の標準形を含む256トークンの文章 |
| 露出回数 | 1 run の学習データに差し込んだ、ある語の用例の数 |
| 条件 (ii) / (i-a) / (i-b) | 実験Bで足す語義の種類。同じカテゴリの名詞 / 別カテゴリの名詞 / 形容詞 |
| N / K | 実験Bで1つのターゲット語に足す語義の数（1, 2, 4） / 1つの donor から差し込む用例の数（暫定3,000） |
| 中立文脈 | 語の意味を示さない文の書き出し（例: "Do you know about the ___"） |
| 最小対 | 手がかりの語だけが違い、ターゲット語の語義がそれぞれ異なる2文 |
| 課題1 / 課題2 | 少数の例を見せてから問い、選択肢の語の対数確率で答えを決める課題。語義の同定 / 属性（カテゴリ・品詞）の判定 |
| 表現 | ある位置での、各層の残差ストリーム（層の出力のベクトル） |
| プローブ | 表現から属性を当てるロジスティック回帰 |
| m / m̂ | 実験Aの指標の値 / それを正規化した値 m̂ = (m − m0) / (m1 − m0)（0が未知の状態、1が既知語に相当） |
| 構成要素 | 各層の attention の head（出力射影の前の、head ごとの出力）と MLP |
| 無効化 | head の出力のうち、特定の方向の成分を平均値に置き換える操作 |

## 必要なもの

- Linux（x86_64）、Python 3.12、[uv](https://docs.astral.sh/uv/) 0.8 以上
- NVIDIA GPU（CUDA 13.0 に対応したドライバ）。目安は次のとおり。LLM を使うコマンドと、GPU で OLMo 2 を使うコマンドは分けてあり、同時には使わない。

| 処理 | GPU |
|---|---|
| 継続事前学習 1B / 7B / 13B | 96GB × 1 / × 2 / × 4 |
| LLM による生成・判定（vLLM） | 96GB × 2 |
| OLMo 2 での評価・分析 | 96GB × 1 |

- ディスク
  - モデル: OLMo 2 の3モデル（約86GB）と LLM（約77GB）。
  - データ（基データ・用例・学習データ）: 約50GB。Pile は保存せず、ストリーミングで読む。
  - 重み（bf16）: 1つあたり 1B 3GB / 7B 15GB / 13B 27GB。60 run すべてで4時点を保存すると約3.6TB（1B 0.24TB、7B 1.2TB、13B 2.2TB）、最終だけなら約0.9TB。
  - 学習中の再開用の状態: 1B 18GB / 7B 88GB / 13B 165GB（run が終われば消す）。
- インターネット接続（下の外部データ・サービスを使う）

## セットアップ

```bash
uv sync
uv run python -m nltk.downloader wordnet
```

LLM を使うコマンド（手順で `# LLM` と書いたもの）の前に、vLLM のサーバを別の環境で起動しておく（サーバの URL は `configs/lam.yaml` の `llm` に書く）。

```bash
uvx --from vllm==0.32.0 vllm serve Qwen/Qwen3-Next-80B-A3B-Instruct-FP8 --tensor-parallel-size 2 --port 8000
```

学習の記録を W&B に送る場合は `uv run wandb login` を実行しておく。送らない場合は、環境変数 `WANDB_MODE=disabled` を付けて実行する。

## 設定と実行の決まり

- 設定は `configs/lam.yaml` にまとめる（モデル、カテゴリ、語数、閾値、シード、LLM、学習・評価の設定。暫定値もここで変える）。LLM の指示文は `configs/prompts/` に版ごとに置く。設定は読み込むときに、必須の項目と値の範囲を確かめる。
- コマンドは `uv run lam <段階> <処理>`。`--config` で別の設定ファイルを使える。
- モデルを使うコマンドは `--model {1b,7b,13b}` で対象を選ぶ（データ作成での確認は3モデルすべてで行う。`train run` はモデルを run の設定ファイルから決める）。GPU は `CUDA_VISIBLE_DEVICES` で指定する。手順の `# GPU` は、GPU で OLMo 2 を使うコマンドを表す。
- 学習以外でモデルに入れる入力は、先頭に `<|endoftext|>` を置く（OLMo 2 は文書をこのトークンで区切って学習しているため）。語は、文脈がないときも先頭スペース付きの形で入れる。
- 各出力ディレクトリに `manifest.json` を書き、そのコマンドが使う設定項目と入力ファイルのハッシュを記録する。どちらも変わっていなければ計算を省く（`--force` でやり直す）。
- run の名前: 実験Aは `run-1`〜`run-8` と `control`。実験Bは `{ii,ia,ib}-n{1,2,4}`（条件と N）と `control-noun`・`control-adj`。

## 手順

### データセットの作成

#### D1. 基データ

```bash
uv run lam corpus base
```

- OLMo 2 ステージ1の学習設定（データの一覧と seed）から、4,096トークンの系列の学習順を再構成する。3モデルの学習設定はデータの一覧と seed が同じなので、学習順も共通になる。
- 学習順の先頭約3億トークンを基データ、その直後の約1,000万トークンを検証データとして、olmo-data.org から必要な範囲だけ取得する。
- 出力: `data/base/{train,valid}.npy`（トークン列）、`data/base/sequences.parquet`（系列ごとの元のファイルと位置）

#### D2. 語の候補

```bash
uv run lam lexicon nouns        # LLM
uv run lam lexicon adjectives   # LLM
uv run lam lexicon unknown
```

- `nouns`: LLM が6カテゴリ（暫定: 食べ物、動物、乗り物、衣類、家具・家庭用品、建物）ごとに、可算の具体名詞の候補とそのカテゴリを出す。WordNet で、そのカテゴリの上位語の下にある語義（synset）を持ち、複数のカテゴリにまたがらない語だけを残し、その語義を「意図した語義」とする。候補は、名詞72語・ターゲット語・自然な名詞に使う。
- `adjectives`: 形容詞の候補を出し、各カテゴリとの結びつきの強さ（LLM の評定）を付ける。候補は、形容詞72語と品詞用の自然な形容詞に使う。
- 名詞・形容詞の候補には、標準形のトークン数、頻度（infini-gram で数えた olmo-mix-1124 と Pile での出現回数）、WordNet の語義の数を付ける。さらに、infini-gram で Pile から無作為に取った出現例50件を LLM で判定し、合格率（名詞は意図した語義で使われる割合、形容詞は形容詞として使われる割合）を付ける。
- `unknown`: near は、6カテゴリに属さない実在語（形容詞・抽象名詞など）から1〜2文字の置換・挿入・削除で作る。far は、ARC 非語データベースの検索フォームから取る（検索の条件は `configs/lam.yaml`）。先頭スペース付きで2・3トークンになり、olmo-mix-1124・dolmino-mix-1124・Pile に一度も現れない（単語の区切りで一致するものを数え、先頭が大文字の形も調べる）ものを残す。
- 出力: `data/lexicon/candidates/{nouns,adjectives,unknown}.parquet`

#### D3. 語の選定

```bash
uv run lam lexicon select
```

- 候補から次の語を選び、役割を付ける（閾値は `configs/lam.yaml`）。どの役割でも、互いに同義語の語と、`data/lexicon/excluded.csv`（D5・D6 で外した語）の語は使わない。合格する用例の数は「Pile での頻度（重複を除いた版に換算）× 合格率 × 窓の除外の後に残る割合」で見積もる。
  - 名詞72語: 各カテゴリ12語。標準形が1トークンで、合格率が閾値以上（ほぼ単義）、合格する用例が10,500件以上と見積もられる語。頻度帯をカテゴリ間でそろえる。
  - ターゲット語18語: 各カテゴリで、標準形が1・2・3トークンの語を1語ずつ。名詞と同じ条件で、合格する用例は500件以上でよい。名詞72語とは重ならない。頻度帯を3つのトークン数の間でそろえ（多トークン語に合わせる）、基データでの出現回数を記録する。
  - 形容詞72語: 標準形が1トークンで、合格率が閾値以上、どのカテゴリとも結びつきが強くない語。頻度帯を名詞72語とそろえ、K = 10,000 でも用例が足りる頻度にする。
  - 未知語72個: 1・2・3トークン各24個。2・3トークンは near・far 各12個を、必要数より多い候補から無作為に選ぶ。最初のトークンが、ほかの未知語やほかの管理対象の語と重ならないものに限る。1トークンの24個には、未使用のトークン番号（100,278〜100,351）のうち先頭の24個を割り当てる。
  - 自然な語: カテゴリ用の名詞（各カテゴリ30語）、品詞用の名詞・形容詞（各60語）、正規化の参照用の既知の名詞（1・2・3トークン各30語）。管理対象の語とは重ならない。
- 名詞・形容詞・ターゲット語には、役割ごとに予備の候補も選ぶ（用例が足りない語の差し替えに使う）。再実行したときも、承認済みの語は変えない。
- 1トークンの名詞12語と、1・2・3トークンのターゲット語各1語がそろわないカテゴリがあれば止まる（設定でカテゴリを替えるか、候補を増やして D2 からやり直す）。
- 出力: `data/lexicon/draft.parquet`（語台帳の案: 語、トークン列、トークン数、頻度、カテゴリ、意図した語義（synset と説明）、役割。予備の候補を含む）

#### D4. 中立文脈の確認

```bash
uv run lam evaldata contexts    # GPU
```

- 文脈なしと中立文脈の候補（`configs/lam.yaml`。初期値は20種）のそれぞれで、学習前の3モデルについて、カテゴリ用の自然な名詞の、文脈の直後での対数確率をカテゴリごとに平均する。
- 6カテゴリの平均からその全体の平均を引いた値を「差のパターン」とし、全文脈の平均のパターンから閾値以上離れた文脈を除く（どれか1つのモデルで離れたら除く）。残った中から離れ方の小さい順に20種を選び、3モデルで共通にする。20種に足りなければ、同じ形の候補を設定に足して再実行する。
- 出力: `data/eval/contexts.parquet`（文脈なしを含む21条件）

#### D5. 語義の近遠の確認と人手確認

```bash
uv run lam lexicon rate          # LLM
uv run lam lexicon similarity    # GPU
uv run lam lexicon finalize --review data/lexicon/review.csv
```

- `rate`: 名詞とターゲット語（予備の候補を含む）から作れる2語のすべての組について、LLM が類似度を7段階で評定する。
- `similarity`: 同じ組について、学習前の3モデルの表現（中立文脈21条件の平均。中間の層 = 1B 8層目、7B 16層目、13B 20層目）の cos 類似度を出し、評定とともに共変量として記録する。同じカテゴリの組が全組の上位半分に、別カテゴリの組が下位半分に入るかを確かめ、人手確認用の一覧 `review.csv` を書き出す。
- `review.csv` は管理対象の語ごとに1行（語、役割、カテゴリ、意図した語義、頻度、近遠の値）。役割に合う語なら `ok` 列に 1、合わなければ 0 を書く。
- `finalize`: `review.csv` を取り込み、語台帳を確定する。0 の語は `excluded.csv` に入るので、`select` から再実行する。
- 出力: `data/lexicon/{ratings,similarity}.parquet`、`data/lexicon/review.csv`、`data/lexicon/lexicon.parquet`（確定した語台帳）

#### D6. 用例

```bash
uv run lam usages collect
uv run lam usages dedup
uv run lam usages judge      # LLM
uv run lam usages review
uv run lam usages finalize --review data/usages/review.csv
```

- 必要数（判定に合格した用例の数）: 名詞は学習用10,000 + 評価用500、形容詞は学習用 K + 評価用500（K の確定までは暫定の3,000）、ターゲット語は評価用500、自然な語は20。評価用の用例は元の語義の評価のために作るが、下の分析では使わない。
- `collect`: Pile を先頭から読み、名詞・形容詞・ターゲット語・自然な語の標準形を含む256トークンの窓（用例の候補）を、出現が中央付近に来るように切り出す。
  - 標準形以外の形（"Pasta"、" pastas"、先頭スペースのない形）、ほかの管理対象の語、URL・コードの中の出現を含む窓は使わない。1つの文書からは3件まで。
  - 語ごとに必要数の3倍に達したら集め終える。再実行すると前回の続きから読む。
- `dedup`: ほぼ同じ候補（8割以上が一致）を除き、元の文書の単位で学習用と評価用に分ける（追加で集めた分も、それまでの分け方を変えずに分ける）。基データと重なる評価用の候補は除く。
- `judge`: LLM で出現ごとに判定する（意図した語義か、慣用句や固有名詞の一部でないか、形容詞は形容詞として使われているか）。出力は合否と理由で、温度0、指示文は版を管理する。判定は保存して再利用する。窓の中の出現がすべて合格した候補だけを用例にし、語ごとに必要数に達したら止める。
- `review`: 名詞・形容詞・ターゲット語について、合格した用例を語ごとに20件抜き出し、`review.csv`（1行1件。語、用例、LLM の理由）を書き出す。正しく判定されていれば `ok` 列に 1、誤りなら 0 を書く。
- `finalize`: `review.csv` を取り込み、語ごとの精度（20件のうち 1 の割合）を記録する。95%（19件）に届かない語があれば止まるので、指示文を直して、その語の `judge` から再実行する。確定した学習用の用例は、シードを固定して無作為に並べ替え、その順を以降の「固定の順」とする。
- 用例が必要数に届かない語は `excluded.csv` に入れ、標準形以外の形で数を補うことはしない。`select` で予備の候補と差し替え、差し替えた語について D5 と D6 をやり直してから D7 に進む（カテゴリ用の自然な名詞を差し替えたときは D4 も）。
- 出力: `data/usages/{candidates,judgments}/`、`data/usages/review.csv`、`data/usages/precision.parquet`（語ごとの精度）、`data/usages/{train,eval}.parquet`（確定した用例と、文中の出現回数）

#### D7. 割り当て

```bash
uv run lam assign build --exp a
uv run lam assign build --exp b
```

- 実験A: 未知語8個と名詞8語のグループを9つ作る（トークン数ごとに3グループ。2・3トークンのグループは near 4・far 4。各トークン数に各カテゴリの名詞4語）。GF(8) による8次の直交ラテン方格で、8 run の「未知語 → 名詞・露出回数」を決める。
  - 露出回数は {0, 1, 10, 100, 1,000, 3,000, 5,000, 10,000}。各未知語は、各露出回数と、グループの各名詞に1回ずつ当たる。名詞と露出回数の組み合わせは重ならず、1 run の中で同じ名詞は1回だけ使う。
  - 2・3トークンでは、各 run の露出0回の3語（各グループ1語）に near と far を両方含める。
- 実験B: 各カテゴリの名詞12語を、ターゲット語のトークン数ごとに4語ずつの枠に分けて1〜4番の順番を付ける。形容詞はターゲット語ごとに4語ずつ無作為に割り当て、1〜4番の順番を付ける。カテゴリの番号を c = 0〜5、トークン数を j として、ターゲット語 (c, j) に次の donor を割り当てる。
  - (ii): 枠 (c, j) の1〜N番目
  - (i-a): 枠 (c+n, j) の n 番目（n = 1〜N。c+n は6で割った余り）
  - (i-b): 割り当てた形容詞の1〜N番目
  - (i-a) の組が D5 の確認で下位半分に入らない（3モデルの cos の平均と LLM の評定のどちらかで、ターゲット語 × 名詞の全組の下位50%に入らない）場合は、コマンドが枠の中の順番を入れ替える。入れ替えても解消しなければ止まる。
- 無作為に決める部分は、設定のシードで固定する。
- 出力: `data/assignments/{a,b}.parquet`、`data/assignments/a_table.csv`（行が未知語・列が run、セルが「名詞 / 露出回数」）、`data/assignments/b_table.csv`（行がターゲット語・列が run、セルが donor の一覧）

#### D8. 学習データ

```bash
uv run lam traindata build --exp a
uv run lam traindata build --exp b
```

- 置換: 用例の中の置換元（実験Aの名詞・実験Bの donor）を、単語の区切りで一致するところだけ、置き換え後の語（未知語・ターゲット語）に置き換える。
  - 直前の a / an を置き換え後の語の語頭の音に合わせ、所有格（'s）は残す。実験Aの1トークン未知語は、文字列を経ずにトークン番号で差し込み、a / an は元のまま残す。
  - 置き換えた後にトークン化し直し、語を含むように256トークンに切り直す。置換元が残った用例や、置き換えが0件の用例があれば、エラーで止まる。置き換えはすべて記録する。
- 実験A: 各 run で、未知語ごとに、割り当てた名詞の学習用の用例を、固定の順の先頭から露出回数ぶん置き換えて差し込む（1 run 171,999件）。対照 run は何も差し込まない（トークン列は基データと同じ）。
- 実験B: 名詞プール（名詞72語 × K 件）と形容詞プール（形容詞72語 × K 件）を、固定の順の先頭 K 件で作る。(ii)・(i-a) の6 run と `control-noun` は名詞プールを、(i-b) の3 run と `control-adj` は形容詞プールを差し込む。割り当てのある donor の用例だけをターゲット語に置き換え、ほかの用例は元のまま差し込む。
- 差し込み: 用例1件を「256トークン + `<|endoftext|>`」の1文書とし、基データの文書の区切りに、4,096トークンの系列の区切りをまたがないように差し込む（差し込んだ分だけ、後ろの基データがずれる）。
  - 挿入位置は学習全体に均等に散らし、同じ実験の全 run で共通にする。各語の用例は、学習全体を露出回数と同じ数の区間に分け、各区間の無作為な位置に1件ずつ置く。
  - 実験Aでは、どの run でも各露出回数に9語（各グループ1語）が当たる。挿入位置は露出回数ごとに9語分を決めて全 run で共通にし、各 run では、その露出回数に当たった語の用例を入れる。実験Bでは donor の番号ごとに K 件分の位置を決める（名詞プールと形容詞プールで共通）。
- 確認（自動）: 語ごとの露出回数（用例の数と出現回数）、置き換えるべき語が残っていないか、総トークン数が同じ実験の全 run で一致するか（実験Aの対照 run を除く）、無作為に抜き出した用例のデコード。
- 出力: `data/train/{a,b}/<run>/`（`tokens.npy`: トークン列、`inserted.npy`: 差し込んだ位置、`replacements.parquet`: 置換の記録、`report.json`: 確認の結果、`samples.txt`: デコードした用例）

#### D9. 評価データ

```bash
uv run lam evaldata natural
uv run lam evaldata refs
uv run lam evaldata pairs     # LLM
uv run lam evaldata tasks     # LLM
uv run lam evaldata check     # GPU
uv run lam evaldata finalize --review data/eval/pairs_review.csv
```

- `natural`: 自然な語の用例から、語を含む1文を取り出す（カテゴリ: 各カテゴリ30語 × 20文、品詞: 名詞・形容詞 各60語 × 20文）。
- `refs`: 実験Aの参照を作る。
  - 実在語らしさのプローブ用に、2・3トークンのそれぞれで、実在語（WordNet の名詞のうち、語台帳の語と重ならないもの）と非語を作る（数は設定）。非語は実在語どうしで2トークン目以降を入れ替えて作り、普通にトークン化しても同じトークン列になり、実在しない（WordNet になく、infini-gram での出現が閾値以下）ものだけを使う。1トークンの負例は `exp-a probe` で作る。
  - 名詞72語を、人工的に2・3トークンに分けた形（例: `pas|ta`、`p|as|ta`）を作る。
- `pairs`: 実験Bの最小対の候補を、テンプレートと LLM で作る（ターゲット語ごと、元の語義と足した語義の組ごとに、確認の後で20組残るよう多めに作る）。
  - 手がかりの語だけが違い、手がかりはターゲット語より前に置き、2文のトークン数をそろえる。
  - 手がかりは、(i-a) はカテゴリ（例: "She peeled the ___." / "She parked the ___."）、(ii) は同じカテゴリの中での区別、(i-b) は品詞（例: "It was so ___." / "It was the ___."）を示すものにする。
- `tasks`: 課題1・2の問題を作る（下の形式）。実験Aは中立文脈21条件の文、実験Bは最小対の文、`check` は自然な語の文を使う。
  - 課題の例（3例）は自然な語の文から選び、課題ごとに固定する。
  - 言い換えの語（ターゲット語18語の元の語義と、例・確認に使う自然な語の分）は、WordNet の同義語と LLM の候補から、標準形が1トークンで管理対象の語と重ならないものを選ぶ。
  - 入れ替えに使う2つの問題（最小対の2文、実験Aの未知語と露出0回の文字列）は語以外を同じにし、トークン数と語の位置が一致することを確かめる。
- `check`: 学習前の3モデルで次を確かめ、使える最小対と課題を記録する。
  - 最小対: 語義 X を示す文では、X をもとから持つ語（donor かターゲット語）を空欄に入れたときの確率がもう一方の語より高く、語義 Y を示す文ではその逆になるか。3モデルすべてで通った組を、1組の語義あたり20組まで残す。
  - 課題: 自然な語に対して、課題1・2が偶然の水準を有意に超えて解けるか（二項検定）。超えないモデルサイズでは、その課題を使う分析を行わず、そのことを記録する。
  - 言い換えの語: 元の語に対して正しく選ばれるか。
  - 残した最小対から、人手の抜き取り確認用の一覧 `pairs_review.csv`（1行1組）を書き出す。手がかりどおりに語義が決まる組なら `ok` 列に 1、そうでなければ 0 を書く。
- `finalize`: `pairs_review.csv` を取り込み、0 の組を除いて評価データを確定する。
- 出力: `data/eval/{natural,refs,pairs,tasks}.parquet`、`data/eval/check.json`、`data/eval/pairs_review.csv`

課題の形式（課題1の例。例は3つ見せる）:

```
Sentence: I put the knife in the drawer.
Question: In this sentence, the word knife means the same as: spoon / blade / bottle / lamp
Answer: blade

Sentence: {評価する文}
Question: In this sentence, the word {語} means the same as: {選択肢1} / {選択肢2} / ...
Answer:
```

- 課題1（語義の同定）の選択肢
  - 実験A: 置換元と、名詞72語のうち別カテゴリの3語。
  - 実験B: 元の語義の言い換えの語（例: car → automobile。名詞72語・形容詞72語と重ならない語）と、足した N 語の donor。
  - 自然な語（例と確認）: 言い換えの語と、別カテゴリの自然な名詞3語。
- 課題2（属性の判定）の問いの行
  - カテゴリ: `Question: In this sentence, the word {語} is a kind of: food / animal / vehicle / clothing / furniture / building`（選択肢は設定のカテゴリ名）
  - 品詞: `Question: In this sentence, the part of speech of the word {語} is: noun / adjective`
- 選択肢は先頭スペース付きで1トークンの語にし、並び順は問題ごとに無作為にする（入れ替えに使う2つの問題では同じ並び順）。
- 語は引用符で囲まない（引用符の直後では先頭スペースがなくなり、学習した形と違うトークン列になるため）。

### 継続事前学習

```bash
uv run lam train plan --exp a --model 7b
uv run torchrun --nproc-per-node 2 -m lam train run --run outputs/runs/a/7b/run-1.yaml   # GPU
```

- `plan`: 実験・モデルごとに、全 run の設定ファイル（モデル、学習データ、シード、学習率、バッチサイズ、ウォームアップ、保存の予定）を `outputs/runs/<exp>/<model>/` に書き出す。全 run は、このファイルを1つずつ `train run` に渡して学習する。
- `run`: 1つの run を学習する（`--nproc-per-node` は GPU の数）。中断したら同じコマンドで続きから再開する。全 run 共通の設定は次のとおり。
  - 学習データは `tokens.npy` の順に使い、シャッフルしない（step s では s × 256 本目からの256系列）。
  - 学習率: ステージ1の最終値（暫定: 1B 7.4e-5、7B 6.2e-5、13B 3.0e-5）。最初の1%の step で0から線形に上げ、その後は一定。系列長4,096、バッチ256系列（約100万トークン/step）。
  - 最適化器: AdamW（β = (0.9, 0.95)、ε = 1e-8、weight decay 0.1（埋め込みを除く）、勾配のクリップ1.0）と、z-loss 1e-5（出力の大きさを抑える補助の損失）。どちらも OLMo 2 ステージ1と同じ。計算は bf16、重みと最適化器の状態は fp32。複数の GPU では重みを分割し（FSDP）、勾配チェックポイントを使う。
  - シード（新しいトークンの初期値の乱数など）は全 run で同じにし、run の違いを学習データだけにする。
  - 実験Aでは、1トークン未知語の入力側・出力側の埋め込みを、既存の埋め込みの平均に小さな乱数を加えた値で初期化する。
  - 損失は、全体と差し込んだ用例だけに分けて記録する。検証データでの ppl（パープレキシティ）を学習前と保存時点で測り、学習前からの変化が1%を超えたら警告する（学習は続け、報告して原因を調べる）。W&B を使う場合はそこにも送る。
  - 学習の25 / 50 / 75 / 100%の時点の重みを、bf16 の Hugging Face 形式で保存する（保存する時点は設定で変えられる。分析には最終の重みを使う）。
- 出力: `outputs/runs/<exp>/<model>/<run>.yaml`、`outputs/checkpoints/<exp>/<model>/<run>/`（`step-*/`: 重み、`metrics.jsonl`: 損失と ppl、`resume/`: 再開用の状態。run が終われば消す）

### 実験A

```bash
uv run lam exp-a probe --model 7b      # GPU
uv run lam exp-a measure --model 7b    # GPU
uv run lam exp-a analyze --model 7b
uv run lam exp-a report
```

- `probe`: 学習前のモデルで、実在語らしさのプローブを層ごと・トークン数ごとに学習する。入力は中立文脈21条件の後に語を置いたもので、語の最後のトークンの位置の表現を使う。正例は実在語、負例は D9 の非語（1トークンの負例は、未知語に使わない未使用のトークン番号50個を、学習時と同じ方法で初期化したもの）。学習に使わなかった語での正解率も出す（パイロットで、プローブが機能するかの確認に使う）。
- `measure`: 各 run の最終の重みで、中立文脈21条件について3つの指標を測る。`control` も同じように測り、差し込みのない学習での値として記録する。正規化の参照（露出0回の未知語、既知の名詞、人工的に分けた置換元）も同じ重みで測り、課題1・2の結果も記録する。取り出した表現は `outputs/activations/a/<model>/` に保存する。
  - 形への慣れ: k 番目のトークンの驚き度 S_k = −log p(t_k | 文脈, t_1, …, t_{k−1})（k ≥ 2）。出力の確率から求めるので、層によらない。3トークンは2・3トークン目の値とその平均を出し、正規化と曲線には平均を使う。1トークンは対象外。
  - 語としての統合: 語の最後のトークンの位置の各層の表現にプローブを当てて、実在語と判定される確率（プローブの学習に使った語は評価に使わない）。
  - 意味の獲得: 語の最後のトークンの位置の各層の表現と、置換元の表現（同じ文脈）の cos 類似度を、21条件で平均したもの。
- `analyze`: m̂ = (m − m0) / (m1 − m0) で正規化する。m1 − m0 が閾値より小さいときは警告し、その値に印を付けて続ける。
  - m0: 同じ run で、トークン数と near / far（1トークンは区別なし）が同じ、露出0回の語の平均。意味の m0 は、露出0回の語と「正規化する語の置換元」との cos の平均。
  - m1: 形と統合は、同じトークン数の既知の名詞の平均。意味は、置換元と、それを同じトークン数に人工的に分けた形（D9 `refs`）との cos 類似度（1トークンは2トークンの値）。
  - 指標ごとに、露出回数に対する m̂ の曲線を混合効果モデル（語・置換元・run の違いを考慮）で求め、m̂ = 0.5 に達する露出回数と、3指標の順番の検定（未知語を単位にしたブートストラップ）を出す。全体と、トークン数別・near / far 別に出す。層は「値が最大の層」と「層の平均」の両方で出し、どちらを使ったかを結果の表に書く。
- `report`: 3指標の推移と層ごとのヒートマップを描き、要因（トークン数・near / far・モデルサイズ）ごとの比較の表を作る。モデルサイズは、結果のそろったモデルどうしで比べる。
- K の確定: 7B の意味の m̂ の曲線を見て、飽和した（それ以上露出を増やしてもほとんど上がらない）露出回数を人が選び、理由とともに `configs/lam.yaml` に書く。
- 出力: `outputs/results/a/<model>/`（`probes/`: プローブ、`measures.parquet`: 正規化前、`normalized.parquet`: 正規化後（接続で使う m̂ を含む）、`curves.parquet`、`order_test.json`）、`outputs/results/a/compare.parquet`、`outputs/figures/a/`

### 実験B

```bash
uv run lam exp-b accuracy --model 7b   # GPU
uv run lam exp-b map --model 7b        # GPU
uv run lam exp-b stats --model 7b
uv run lam exp-b encode --model 7b     # GPU
uv run lam exp-b causal --model 7b     # GPU
uv run lam exp-b report
```

- 最終の重みで、最小対の文を課題に入れて使う。ターゲット語の位置は、Sentence 行の語の最後のトークンとする。
- 最小対 (s_X, s_Y) では、s_X が語義 X、s_Y が語義 Y を手がかりで示す。Δ(s) は、課題1での log p(語義 X の選択肢) − log p(語義 Y の選択肢)。
- B1・B2 は課題1を使う。B3 は、カテゴリでは (i-a) の最小対とカテゴリの課題2を、品詞では (i-b) の最小対と品詞の課題2を使う。

- `accuracy`（B1: 使い分けの確認）: 課題1の正解率を、どちらの語義を手がかりにした文でも測り、対照 run（(ii)・(i-a) は `control-noun`、(i-b) は `control-adj`）との差で出す。偶然の水準を有意に超えない（二項検定）ターゲット語・語義は、B2・B3 から外して記録する。
- `map`（B2: head の地図）: s_X の処理で、構成要素 c のターゲット語の位置の出力を s_Y での出力に入れ替えたときの Δ を Δ_c とし、効果 e_c = Δ(s_X) − Δ_c と、正規化した e_c / (Δ(s_X) − Δ(s_Y)) を出す（1なら語義 Y に完全に切り替わった）。
  - まず勾配による近似（attribution patching）で全構成要素を測り、上位50個と無作為な50個を実際の入れ替えで確かめる（近似と実測の一致も記録する）。
  - 対照 run での効果を引き、両方向（X→Y、Y→X）・全組で平均する。補足として、ターゲット語より後の全位置での入れ替えの地図も作る。
- `stats`（B2）: ターゲット語と最小対を単位にしたブートストラップの信頼区間と、FDR 5%（構成要素の数についての多重比較の補正）で、有意な構成要素を選ぶ。
  - 効いている条件で分類する（すべて: 語義選択そのもの、(i-a) と (i-b): カテゴリの判定、(i-b) だけ: 品詞の判定、(ii) だけ: 同じカテゴリの中での区別、それ以外: 個別に記述）。
  - N に対する傾きが正で、ターゲット語を2つに分けた両方で再現するものを採用する（各トークン数3語ずつの9語ずつに分け、カテゴリはできるだけそろえる。分け方はシードで固定し、逆方向でも確かめる）。
  - 語義の近遠の値と基データでの頻度は、共変量として結果の表に付ける。
- `encode`（B3: 符号化）: 採用した head ごとに、その出力からカテゴリ（6クラス）・品詞（2クラス）を当てるプローブを、学習前のモデルで、自然な語の文を同じ課題2の形式に入れて学習する。(a) 学習に使っていない自然な語（語の単位で分ける）と、(b) 語義を足したモデルの最小対（手がかりが示す語義の属性を当てる）での正解率が、どちらも偶然の水準を有意に超えるかを見る。head の出力は `outputs/activations/b/<model>/` に保存する。
- `causal`（B3: 因果と特異性）: プローブの重みが張る部分空間（属性の方向。カテゴリは最大5次元、品詞は1次元）の成分だけを、課題2の s_X の処理で s_Y での値に置き換える。
  - 答えが s_Y の属性に変わる割合とその対数確率の変化、課題1の Δ の変化を測り、同じ層の無作為な head・同じ次元数の無作為な方向での値と比べる。
  - 特異性（カテゴリは (i-a)・(i-b) で効き (ii) では効かない、品詞は (i-b) で効く）も確かめる。符号化・因果・特異性を満たした head を「その属性の判定を担う head」とし、部分空間とともに保存する。
- `report`: 層 × head の地図と、N・トークン数・モデルサイズ別の比較の表と図を作る。
- 出力: `outputs/results/b/<model>/`（`accuracy.parquet`、`maps.parquet`、`components.parquet`、`encoding.parquet`、`heads.parquet`: 判定を担う head、`subspaces/`: 属性の方向）、`outputs/results/b/compare.parquet`、`outputs/figures/b/`

### 接続

```bash
uv run lam connect dependence --model 7b   # GPU
uv run lam connect analyze --model 7b
uv run lam connect map --model 7b          # GPU
uv run lam connect report
```

- `dependence`: 実験Aの各 run の最終の重みで、同じモデルサイズの「カテゴリの判定を担う head」（実験Bの `heads.parquet`・`subspaces/`）の出力のうち、カテゴリの方向の成分を自然な語での平均に置き換える（無効化。位置は Sentence 行の語の最後のトークン）。
  - 平均は、無効化するのと同じ重みで、自然な語の文をカテゴリの課題2の形式に入れて取る。head が複数あるときは全部を同時に無効化した値を本分析とし、head ごとの値も記録する。該当する head がないモデルサイズでは行わず、そのことを記録する。
  - 中立文脈21条件の課題2で、正解カテゴリ（置換元のカテゴリ）の対数確率の低下を、未知語（d_未知）と置換元そのもの（d_既知）について測る（21条件の平均）。依存度 = d_未知 / d_既知。d_既知 が閾値より小さい（その head が既知語にも効いていない）置換元と run の組は除く。
  - 同じ層の無作為な head・同じ次元数の無作為な方向でも同じ操作をする。無効化する前の課題2の正解率も記録する。
- `analyze`: モデルサイズごとに、依存度 ~ 意味の m̂ + 統合の m̂ + トークン数 + near / far + (1 | 未知語) + (1 | 置換元) + (1 | run) を当てはめる（(1 | x) は x ごとのランダム切片）。
  - 露出0回の未知語も含める。m̂ は、実験Aの順番の判定と同じ層の選び方で1つの値にする。near / far は、1トークンでは「なし」の水準とする。
  - 意味・統合の m̂ が閾値（0.3 / 0.5 / 0.7）以上か未満かで状態（例: 「意味はあるが統合はまだ」）に分けて比べ、結論が変わらないかも確かめる。
- `map`: 未知語ごとに、実験Aの地図（課題1で、未知語の位置の各 head の出力を、同じトークン数の露出0回の文字列での出力に入れ替えたときの、正解の対数確率の低下。露出0回の語は除く）と、実験Bの地図（その未知語の置換元が donor になっている語義の地図。(ii)・(i-a) の各 run）を比べ、head ごとの効果の順位相関と、上位の head の重なりを出す。
- `report`: 意味・統合の m̂ と依存度の関係の図（モデルサイズ別）と、閾値を変えた結果の表を作る。
- 出力: `outputs/results/connect/<model>/`（`dependence.parquet`、`regression.json`、`thresholds.parquet`、`maps.parquet`）、`outputs/figures/connect/`

### 集計

```bash
uv run lam results collect
```

- 全結果を1つの縦長の表（実験、モデル、run、語、条件、N、指標、層、head、値）にまとめ、標準の図（推移、層ごとのヒートマップ、層 × head の地図）を作る。
- 出力: `outputs/results/all.parquet`、`outputs/figures/`

## 実行の順序

1. データセットの作成（D1〜D9）。実験Bの学習データ（`traindata build --exp b`）だけは、K の確定後に作る。
2. パイロット: 7B で実験Aの `run-1` と `control` を学習する。学習率・バッチサイズ・ウォームアップ・新しいトークンの初期値を確定して `configs/lam.yaml` に書き、ppl の変化と、プローブが機能すること（学習に使わなかった語での正解率）を確かめる。値を変えたら、2 run を新しい設定で学習し直す。
3. 実験A: 7B の全 run を学習・評価し、K を確定する。
4. 実験B: 形容詞の用例が K + 500件に足りなければ、追加で集めて判定する（`usages collect` → `dedup` → `judge` → `review` → `finalize`）。`traindata build --exp b` で学習データを作り、7B の全 run を学習・評価する。
5. 接続: 7B で行う。
6. 1B・13B で、実験A・実験B・接続の学習と評価を行う。学習率は、パイロットで決めた決め方を各モデルに当てはめる（暫定では各モデルのステージ1の最終値）。K とほかの設定は 7B で確定したものを使い、決め直さない。
7. 集計: `results collect`。

```
data/

```
